How to read this — Binary Obelisk

The beads tower and the bo loop dispatcher, drawn from the plugin's .claude/CLAUDE.md (which transcribes binary-obelisk-v1-design.yaml). Open any node for its full description — the first line always says what it is.

Colors = who owns it

  • Blue — the dispatcher (bo loop)
  • Purple — worker agents (engineer, testers, review, merge)
  • Teal dashed — plan agents (they build the tower, then stand down)
  • Cyan — the Stop hook (fail-closed gatekeeper)
  • Amber — gates; only a human closes them
  • Slate documents — tickets (beads issues)
  • Gray — infrastructure (beads DB, GitHub, the human, notes)
  • Red dashed — errors that pop up
  • Green boxes — branch worktrees; one box per branch

Arrows

  • blocks (dashed gray) — the depends-on chain; read left to right, oldest first
  • dispatches (blue) — one edge per dispatching label; the label alone picks the worker
  • works (purple) — agent points at the ticket its label owns
  • plans (teal dashed) — top-down tower build
  • closes (amber) — human to gate; nothing else closes a gate
  • raises (red dotted) — where an error pops up

Read the views in this order

  1. Maps 1 — the tower: epic, two features, every ticket
  2. Maps 2 — the branch boxes (.claude/worktrees/)
  3. Walkthrough 1 — plan the tower top-down
  4. Walkthrough 2 — one tick of bo loop: claim, label, branch, worktree, spawn
  5. Walkthrough 5–9 — the stages: back ends in parallel, then unit tests, then UI, then the suite and review, then the epic tier
  6. Walkthrough 3 — worker, Stop hook, gate (the $BO_DONE_FILE safety)
  7. Walkthrough 4 — the epic tier assembles
  8. Walkthrough 10 — every error and who raises it

Walkthroughs

Dynamic views read top to bottom as numbered steps; each step carries notes with the real payload (the claim JSON, the metadata, the git command). Alt boxes are either/or decisions; try/catch is the failure path. In element views, a box that repeats across views is the same element, not a copy — follow its link to the view where it continues.

Glossary

  • gate — a checkpoint, not work; invisible to bd ready; human-closed
  • dispatching label — the one label that names a worker; a ticket must carry exactly one
  • respawn — a fresh session of the same agent re-checks the work inside the one ticket
  • frontier — the tickets bd ready --claim can hand out right now
  • left claimed — the ticket parks behind its own lease, off the frontier, until a human looks
  • done marker — $BO_DONE_FILE; the Stop hook commits, pushes, opens the PR, and closes only when it exists
